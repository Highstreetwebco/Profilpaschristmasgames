# Profilpas 2026 Christmas Games

A shared four-player games centre for Richard, Stu, Jack and Lauren. Jack is the ringmaster and controls the whole room.

Live site: https://profilpas-christmas-games-2026.jackmoycetroth.chatgpt.site

GitHub Pages entry: https://highstreetwebco.github.io/Profilpaschristmasgames/ — the root `index.html` redirects to the live game because its shared backend runs on Sites. `.nojekyll` prevents Pages from rendering this README as the website.

Source: https://github.com/Highstreetwebco/Profilpaschristmasgames

## Player flow

1. Each person opens the same link on their device and chooses their own name. No account or sign-in is needed. Whoever selects Jack becomes the ringmaster.
2. Their card becomes ready on every screen. A name cannot be claimed twice.
3. Jack can start with the ready, connected players, including alone for testing. Lauren jumps out of her card, runs beneath the existing top-left header logo, throws a rope, pulls the old logo down, throws the supplied replacement into place, and returns to her card. The shared game menu opens automatically after the 18-second scene (plus a 2.2-second synchronisation lead-in).
4. Jack selects a round; all screens follow automatically.
5. Game one is Pictionary: each participating player draws twice in roster order (eight drawings with all four players). The drawer clicks “Reveal my word & start” for a random secret word and 120 seconds. Everyone else sees the shared pad and can keep typing guesses. The first correct guess automatically ends the turn and wins exactly one point. Time expiring reveals the word without awarding points. Jack advances to the next drawing.
6. The pad supports mouse, touch and stylus, seven colours, an eraser, four brush sizes, undo and clear. No letters, numbers, speaking or gestures while drawing. Solo practice gives Jack two drawings and a guessing-box test, without awarding points.
7. Game two is cooperative Hangman (“Save the Elf”). Each player sets one secret word in an assigned work category: colleagues, customers/suppliers, tiling tools, products/profiles, materials/finishes, installation/site work, sales/office or brands/ranges. Names, short words such as Stu, and hyphenated phrases are supported (2–24 letters, 32 characters overall). The setter confirms relevance, team familiarity and spelling before locking it. Everyone else shares six mistakes and can submit a letter or a whole answer. A wrong answer costs one chance; duplicate guesses never cost an extra chance. Saving the setter’s avatar awards each guesser 1 point, with no reward for stumping the team. Each wrong guess adds a head, body, arm or leg to the elf; its head is the setter’s actual avatar. Solo practice supports both roles without scoring. Jack can pause, end a disputed word, or move to the next setter.
8. In Memory Match, study 24 picture cards for eight seconds, then everyone clears their own copy of the same layout. Fewest card flips wins: first gets 5 points, second 3, third 1, and last place is called Nob head. Scores are awarded once everyone finishes.
9. Game four is four-player Battleships. Each captain selects and moves three ships with arrow controls and Rotate on a private 8×8 sea, then confirms positions. The final confirmation starts the battle automatically. On your turn, click any untried square on a surviving opponent’s board to launch one missile. Hit or miss, the turn passes. The last fleet afloat wins: 5 points for first, 3 for second, 1 for third, 0 for fourth.
10. Solo Battleships adds Santa’s Navy as a computer opponent and never awards competition points. Only Jack can choose games, control round progression, pause, adjust scores, return everyone to the lobby, reset the session or show the podium.

Refreshes restore the selected player. Presence expires after 20 seconds without a heartbeat. Jack can release a guest slot in the lobby if someone changes browser or device. A return to the lobby preserves scores but requires everyone to ready up again; Reset session clears scores and round progress.

## Shared state and authority

The site now runs a Vinext/Cloudflare Worker with its own D1 database. It polls shared state every 1.5 seconds, increasing to every 500 ms during all four games. Drawing points are streamed in small batches about every 180 ms; local ink appears immediately. Ready status, active round, answers, timers, scores and stage changes are shared between devices. Polling failures pause controls rather than pretending the room is connected.

There was no dedicated Christmas project in the connected Supabase account, only an unrelated Barford golf project. That project was not changed. The game database is provisioned by Sites via the `DB` binding.

Anyone with the game link can enter without signing in. Selecting Jack gives that browser the ringmaster controls; the other three names are players. A random HttpOnly Secure SameSite cookie remembers each browser, and only a hash is stored in the room. Host authority is based solely on the selected Jack slot, with no email or platform account requirement. An active name cannot be claimed twice. In the lobby, a name becomes available to another browser after its previous device has been disconnected for 20 seconds.

Changes use a versioned compare-and-swap write with retry so concurrent answers and joins are not lost. Actions carry request IDs; stale card actions are rejected. The Pictionary deck and randomly chosen prompt IDs stay on the server; only the active drawer receives their word after starting. Even Jack receives no secret when guessing. Draw, undo and clear commands require the current drawer, round instance, turn and canvas revision. A compare-and-swap retry resolves concurrent correct guesses to one winner. The 120-second deadline is enforced by the server and appears finished on polling clients even without a browser completion command. Common word aliases, case, punctuation, spaces and leading articles are accepted. Drawings and guesses are bounded and reset between turns; the current pad survives refresh and pauses. Hangman likewise filters its submitted secret out of all other players’ API responses, including Jack and observers, until the result. Letter reveals, shared mistakes and cooperative points use the same atomic room writes. Category relevance is confirmed by the setter; there is no dictionary or semantic validation of custom colleague/customer names. No database migration is required.

## Screen fit

The header, score strip and host dock use compact layouts. Every game is fitted into the remaining viewport by `StageFit`, using actual element measurements and ResizeObserver/MutationObserver. It responds to window changes, loaded fonts and the mobile visual viewport, including the on-screen keyboard. Any residual oversized stage is scaled as a complete unit so controls remain visible. The Pictionary pad has a height limit and maps pointer input through the SVG screen transform so resize and scaling do not move the ink away from the pointer. Small screens display the latest guess rather than requiring history scrolling. Help/score dialogs retain their own scrolling if required.

The sizing calculation has automated coverage for laptop, desktop, tablet, phone, landscape and keyboard-reduced dimensions. This verifies the fit calculation, not browser layout. Browser rendering remains unverified because managed browser QA is unavailable in this environment.

## Memory Match (game three)

A 24-card challenge replaces the 30-Second Dash. Four approved elf portraits plus eight generated picture sprites form 12 pairs, with one picture per tile. A cryptographically shuffled layout is stored in the room. Jack starts a synchronised eight-second preview after a short lead-in; each participant then clears their own copy independently. Everyone must find all 12 pairs. Each accepted face-down card flip counts as one click (a perfect board takes 24); a miss shows both pictures for 1.6 seconds before hiding them. Matching cards stay visible on that player's board. Other players see click counts and progress, never each other's selected positions or revealed pictures. Hidden card responses contain no picture identifiers. Refresh retains personal progress.

After everyone finishes, the server ranks the fewest clicks first and awards 5 points for first, 3 for second, 1 for third and 0 for fourth. The most-clicks finisher gets the “Nob head” label. Equal click counts share the same place and points with competition ranking (e.g. 1st, 1st, 3rd, 4th), regardless of finishing speed. Tied last-place players share the label, unless everyone ties. Solo practice records clicks and a result without competition points or a losing label. Two- and three-player sessions use the same points by place. Completed boards cannot be replayed to accumulate scores.

The server authenticates the player, board ID and personal selection revision. Idempotent request IDs and atomic room writes protect simultaneous play, retries and scoring. Invalid, duplicate, already-matched and disabled card clicks do not increase the counter. Awards happen once, on the last participant's final match; no points are given per pair. Jack can pause/resume everyone's board. Menu/lobby navigation freezes the preview and each reveal timer, retaining clicks and pairs. Pause conceals unmatched pictures. Disconnected players can resume their saved board; final scoring waits for them. Results replace the card grid until Jack finishes the round.

Existing boards from the former shared-turn version restart Memory under the new rules, retaining the shuffled layout. Their obsolete per-pair awards are removed; all other game progress, scores and manual adjustments remain intact. No database schema migration is needed.

The 6×4 desktop board becomes 4×6 on phones, with StageFit keeping the board, results and controls within the available viewport. Reduced motion removes the 3D flip. Artwork provenance is in `docs/memory-artwork.md`. Automated tests cover independent private boards, concurrent requests, accurate click counts, rankings, ties, migration, pauses and solo practice. Browser layout/pointer validation remains unavailable in this environment.


## Battleships (game four)

Battleships replaces Sell It to Santa. Each participant has a private 8×8 grid with a cruiser (4 cells), frigate (3) and patrol boat (2). Initial fleets are random and valid. Setup shows only your own board. Select a ship using its button or a ship square, move it one square with the directional arrows (or keyboard), and rotate with the button or R. Every move is saved and checked on the server for grid bounds and overlap; ships may touch. Invalid movement buttons are disabled. Shuffle remains available. Confirm positions marks that captain ready for everyone and shows a readiness notice. Players can change positions again until the final confirmation, which atomically starts the battle without a separate host launch. No ships can move once it starts. Turn order is shuffled once and survives refresh.

On each turn the captain selects any surviving opponent and fires once. Both hits and misses pass to the next surviving captain. All players share the shot history for each target, so a square cannot be hit again by another attacker. Only the owner receives ship positions, including after ships sink or the battle ends; everyone else sees only red hit pegs and blue miss pegs. Jack and observers receive no hidden fleet coordinates. Eliminated captains stop firing but can watch all boards and the commentary.

The last surviving fleet wins. Survival order awards 5/3/1/0 points once; hits and final-hit kill steals do not award extra points. Final standings include shot/hit counts; enemy ship silhouettes remain hidden. Jack finishes the round. Existing scores from other games remain unchanged, and an old active pitch screen safely returns to the game menu. Reset session clears all old test progress and scores.

Authenticated commands carry a battle ID, a personal fleet revision for placement and a turn revision for firing. Atomic D1 writes and request IDs prevent concurrent shots or retries from taking extra turns or duplicating points. Host pause/menu navigation retains fleets, the active captain and shot history. An already-launched missile finishes on its shared clock; pause prevents further shots. Only a disconnected current player (no heartbeat for 20 seconds) can be skipped by Jack; their fleet remains targetable. A returning player resumes the same fleet.

With only Jack participating, Santa’s Navy is a computer captain with its own hidden fleet. It responds automatically, follows up public unsunk hits and otherwise chooses an untried square. It does not select shots using unhit ship positions. Either side can win, and neither receives competition points.

Once every captain confirms, all four boards appear together in a compact 2×2 wooden frame on desktop and mobile, matching the supplied reference. The board list uses all server fleets independently of firing order. Only your board shows ship silhouettes. Clicking an untried square directly on any opponent’s board fires immediately, once per turn, with no additional fire button. The existing measured stage keeps the complete game and its controls within one screen. Solo practice shows two boards.

Every accepted shot gets a persisted shared animation timeline. An SVG missile flies along a continuous curve from the attacking board to the selected enemy square, pointing along its flight path. A large layered fireball and brief impact shake mark hits; a blue water crown, droplets and ripple mark misses. Pegs and fleet damage become visible at impact. The server blocks the next shot until playback ends, queues the computer reply after the player’s animation, and delays the results screen until the final scene finishes. Reloading resumes the current scene without replaying expired sound cues.

Locally synthesised launch and flight sounds, explosions and splashes accompany generic device English speech voices. Hits cycle through 17 rude lines including “Fuck you!”, “Take that, nerd!”, “Eat shit, motherfucker!” and “Missile up the arse!”. Misses, sunk ships and retaliation have their own captions, with the bespoke Richard patrol-boat joke. Reply timing allows the first caption to finish before the next begins. Audio requires a gesture and has a persistent on/off control. Captions work independently. Reduced motion removes missile flight and impact shake while preserving results and captions. Existing portraits and native SVG ships are reused; no new image assets or database migration are required.
